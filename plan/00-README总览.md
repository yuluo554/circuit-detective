## 二、决策记录

> **D1–D3 是本题的定位生死线，任何里程碑都不得削弱。**

| 编号 | 日期 | 决策 | 理由 / 弃选 |
| --- | --- | --- | --- |
| **D1** | 2026-10-17 | **题材虽小众，但首关不出现"门""NAND"字样，只叫"黑盒"；第 3 关才引入 AND / OR 的正式名称** | 题材门槛是最大的流失点。第一屏必须让完全不懂电路的人也能玩：只有"拨杆 / 灯 / 黑盒"。术语在玩家已经理解"拨一下会变"之后再给名字，把学习曲线藏在玩法后面。若首关就写"逻辑门"，等于把 NandGame 的受众当成全部受众。 |
| **D2** | 2026-10-17 | **三个 0★ 前车之鉴全部失败在"做成真值表填写"，本题必须坚持可视化揭示**：提交后门电路**逐层点亮**，而不是弹一张对错表 | `ctkrug/circuitle`、`Dhananjay-ku-seth/circuit-puzzle`、`mengyihh233/nand-to-cpu` 都把反推做成了表格作业：没有拨杆、没有灯、没有试探的乐趣。**只要本题的提交结算退化成表格，就重蹈覆辙**——这条是失败判据，不是建议。 |
| **D3** | 2026-10-17 | **日期哈希种子可被客户端提前算出：可接受，但砍排行榜** | 纯前端不可能藏住当天种子；玩家改系统时间或直接算哈希就能预知答案。本题不把"防作弊"当目标（单人解谜，作弊只损失自己的乐趣），但**绝不做好胜心驱动的排行榜**——没有后端就不可能有可信排名。 |
| D4 | 2026-10-17 | 交付形态收敛为**唯一**：纯前端单页 Web 游戏 | 不设"CLI 版 / 桌面版 / 小程序版"备选。形态留后门会给空壳通行证；本题的全部价值在浏览器里的即时反馈。 |
| D5 | 2026-10-17 | **零框架、零 CDN、零美术资源** | 体积目标 <150KB gzip（以末态实测回填）；无外链才能断网可玩、才能被静态扫描断言。门与走线全部用 Canvas2D 几何图形绘制。 |
| D6 | 2026-10-17 | 三值逻辑（0 / 1 / X）与 unit-delay 语义写进 `data/README.md` §四，**单点定义** | 仿真核、求解器、渲染、文档共用一套口径；任何模块不得自行解释 X 的传播。 |
| D7 | 2026-10-17 | **求解器即裁判**：最优门数由求解器给出，禁止人工标注答案 | 人工标注会漂移、会错、也无法解释"为什么是 3 个门"。求解器同时承担生成期的可解性复核。 |
| D8 | 2026-10-17 | 关卡生成用 **xorshift128+**，同 seed 字节级相同 | 不用 `Math.random`、不用时间、不依赖对象键序与区域设置；每日题 = 日期字符串哈希成 seed。 |
| D9 | 2026-10-17 | 回放用**短码**（≤64 字符，URL 安全字符，带版本前缀与校验位） | 长 URL 无法口头分享；版本前缀保证旧码在新版本上要么可解、要么明确报不兼容，不静默错解。 |
| D10 | 2026-10-17 | 门基首期限定为 **AND / OR / NOT**（4 输入、4 输出） | NAND 单独成门会让等价类归约变复杂；首期先把判定链跑通。扩展门基（NAND / XOR / MUX）留二期。 |
| D11 | 2026-10-17 | 进度只存 `localStorage`，不设账号与云存档 | 无后端；清空即失是可接受的代价，换来零上传。 |
| D12 | 2026-10-17 | 品牌隔离：本题只做"黑盒反推解谜"，不复用本系列任何工具项目的命名、素材、文档模板 | 游戏与工具是两种受众，交叉引用会污染定位与检索。 |
| D13 | 2026-10-17 | M6 产物口径采用 **A) Release 附产物** | 单文件构建产物是本题的交付物；源码 zipball 不能替代"能直接打开就玩的那一个文件"。 |

### 弃选项（候选方向，均已否决）

| 弃选项 | 弃因 |
| --- | --- |
| **生成式视觉玩具** | 无判定内核：好看但不可判对错，也没有"最少步数"这类可证明的分数；且该方向已被大量同类项目挤满。 |
| **ASCII 动画 / 手绘风格演示** | 视觉风格已在本系列与同类项目中占位，且无法承载"拨杆—灯—揭示"的交互密度。 |
| **落沙 / 粒子沙盒** | `sandspiel` 3209★、`sandboxels` 468★ 已占位，正面撞车且无判定内核。 |
| **排序算法可视化** | `algorithm-visualizer` 48904★，绝对红海，且与本题的"信息受限反推"无关。 |
| **程序化音乐工具** | Tone.js 14779★、helio 3571★ 已占位；且音频跨设备浮点差异会破坏确定性。 |
| **本地多人联机（WebRTC）** | 一周内无法保证两端确定性一致（时钟、丢包、浮点），与"可复算回放"的立题基础冲突。 |
| **音色谜题（听音反推）** | `OfflineAudioContext` 跨设备浮点差异只能做容差判定，破坏"逐项相同"的验收口径。 |
| **机关 / 物理沙盒** | 物理引擎的确定性调优与关卡设计成本远超一周 MVP，列二期。 |
| **排行榜 / 全球排名** | 无后端，日期种子可提前算出，排行榜必然可刷（D3）。 |
| **AI 生成关卡** | 关卡必须求解器可证明；模型生成的关卡无法保证有解、无歧义，也无法给出最优门数（§六）。 |
