## 八、CI 说明

`.github/workflows/ci.yml` 在 M0 落盘，长时间**无远端、从未真实执行**；本地只做两件事：

1. 用 `node -e` 解析 YAML 并断言 job / step 数（防"纯量里含 `: ` 导致 0 job"）；
2. 在本机按 workflow 的每一步逐条手工复跑（`npm test`、`npm run verify`、`npm run build`）。

**2026-10-18：首推 `main` 后已实跑**（run `39138019748`）。矩阵 `os × node` = 4 个 job 全绿，
步骤与本地等价校验一致（fixture 字节复核 → `npm test` → `npm run verify` → `npm run build` → `check-dist`）。
本仓**刻意不把** `smoke` / `verify:engines` 放进 CI（需要代码仓外的 playwright 浏览器缓存）。

按 sprint 纪律，本仓在首推**之前**从未在 DoD 里写"CI 绿"；现在写的是实测结论（§七）。

**本轮修掉的真实缺陷**

1. **短码里的 64 bit seed 还原成负数**（D25）：`decodeRecord` 用 JS 有符号位运算一次读 32 bit，高位字最高位为 1 时返回负数，`BigInt(负数)` 拼接得到负 seed。此前 `replay.crossInstance` 只比探测输出、不比 seed，缺陷潜伏到 M4 才暴露（回放视图要把 seed 显示出来、降级文案要用种子）。
2. **冒烟脚本超时不给报告**：`waitForFunction` 超时会以"未捕获异常"中止，日志里只剩一行 Timeout，看不出哪些项已经过。现在 `uncaughtException` / `unhandledRejection` 都接住并打印完整对账表。
