## 二、M0 新增决策（D14+）

| 编号 | 日期 | 决策 | 理由 / 弃选 |
| --- | --- | --- | --- |
| **D14** | 2026-10-18 | **最少门数口径 = 每个输出锥内部门数之和；共享门按使用它的输出各计一次；未使用门不计分** | 原题面只写"最少门数"，未定义多输出如何合并。若不定义，任何求解器结果都不可复核。弃选"全图门数"（玩家摆共享门会被惩罚，鼓励复制粘贴）与"按 DAG 节点数"（与玩家直觉不符：一个门喂两个灯应算两次使用）。口径进 `data/README.md` §4.3，界面必须写明。 |
| **D15** | 2026-10-18 | **求解算法 = 二输入 AND/OR + NOT 的公式复杂度成本表（16 位掩码，按门数递增分层）** | 4 输入布尔函数的可达掩码仅 62,786 个，成本表 14ms 内建完，生成 10k seed 仅 2.3s。弃选"逐关卡 A* 搜索"（慢且难以给出"可证明"的界）与"枚举网表结构"（状态爆炸）。代价：口径是**公式复杂度**而非"任意 DAG 的最小节点数"，已在 D14 与界面文案中声明，不冒充理论绝对最优（对应 plan/01 §六 结论纪律）。 |
| **D16** | 2026-10-18 | **求解器成本表按"输入变量数 × 门数上限"缓存，进程内只建一次** | 成本表与具体关卡无关；每关重建会让 10k seed 从 2s 变 10 分钟。测试断言两次调用返回同一对象（缓存有效）而非重新计时。 |
| **D17** | 2026-10-18 | **不引入打包器；自写 `tools/bundle.mjs` 做依赖序拼接** | 零依赖是隐私与体积承诺的一部分；15 行拼接足以处理本项目的扁平 ESM。弃选 esbuild/rollup（多一个 dev 依赖与锁文件，且会让 CI 装包）。代价：不支持 tree-shaking / 循环 import —— 本项目依赖方向单向，`core` 内无循环。 |
| **D18** | 2026-10-18 | **fixture 形态配额按 `index % 5` 固定分配，不按随机** | 随机分配会出现"某形态 0 条"的静默缺口（本项目首版造环逻辑写错，200 条 cyclic 实际 0 条有环）。固定配额 + `verify` 断言形态计数，缺口立刻变红。 |
| **D19** | 2026-10-18 | **`verify` 的 `--require` 未知项报 FAIL，不静默跳过** | 首版 `--require core` 既不匹配任何段名也不报错，输出"全绿"但一段没跑（典型的"没扫到"伪装成"扫干净"）。 |
| **D20** | 2026-10-18 | **前 3 关成"拼块 / 插口"话术，第 4 关才出现门名** | D1 的落地方式。玩家可见文案全部集中在 `src/ui/copy.mjs`，前 3 关用 `BASIC` 词表、第 4 关起用 `FULL`；`verify` 的 `copy.terms` 段含阳性对照（扫描器必须能抓到禁用词），避免"扫了个空集"。 |
| **D21** | 2026-10-18 | **门数口径改为"按引用展开计数"（原实现按锥内去重）** | M3 实测：按锥去重会在 1/10000 的关卡上给出 `你的门数 < 最优门数`（seed 9497：6 vs 7），与 §4.4「差值 ≥ 0」直接冲突。改为逐输出按引用展开后，差值恒非负且等于公式规模之差；共享门仍按每个灯各计一次，口径文字不变、判定语义变严。弃选"保留去重 + 把差值钳到 0"（会掩盖真实差异）。 |
| **D22** | 2026-10-18 | **生成器剔除恒等冗余门 `AND(x,x)` / `OR(x,x)`** | 实测 10000 关里 4864 个含这类门的引用（约一半关卡）。它们功能上等于直连，却让隐藏实现多出一个玩家无法观测的结构，导致"照答案拼装"仍得到差值 1。剔除后最优解与隐藏网表门数关系恢复自洽（中位差 0）。 |
| **D23** | 2026-10-18 | **编辑器采用"点选引脚"而非拖拽改线（落定 Q1）** | 键盘可达（方向键移动、Delete 删除、数字键拨杆）、实现量小、移动端点按可行。拖拽只用于移动零件位置，不承担接线。 |
| **D24** | 2026-10-18 | **命中判定按距离取最近，而非按类型优先** | 首版"引脚 > 插口"的顺序让相邻拼块互相抢点击：点 A 的输出实际命中 B 的输入，端到端冒烟实测复现（`g03` 的引脚未接上）。改为同优先级内取最近距离。 |

## 四、风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 公式复杂度口径与玩家直觉不符（造了共享门却被计两次） | 结算争议 | 结算面板明写"按每个灯单独计门"；D14/D21 留档；关卡生成时偏向低共享结构 |
| 求解器选出的关卡"最优门数"偏高（4–8 门），早期关卡不够轻 | 新手流失 | **已缓解（M3）**：战役前 3 关 `gateBudget:2`，实测最优恒为 2 门；`verify` 的 `campaign.early` 段常驻断言 |
| 相邻拼块的引脚互相抢点击 | 接不上线 | **已修复（D24）**：命中按距离取最近；端到端冒烟覆盖"逐引脚点击照答案拼装" |
| 隐藏网表含恒等冗余门，照答案拼装仍有差值 | 玩家困惑 | **已修复（D22）**：生成期剔除；测试常驻断言 |
| 短码在门数满 12、探测 40+ 步时接近 64 字符 | 分享失败 | 已有超长显式报错；M4 允许"仅分享 seed + 探测数"降级文案 |
| Canvas 在小屏被压缩，点击命中区偏移 | 移动端不可玩 | 首期只保证桌面；DPI 缩放已按 `canvas.width / clientWidth` 换算 |
