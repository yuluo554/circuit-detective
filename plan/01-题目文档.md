# 10-19-circuit-detective · 黑盒电路侦探（题目文档）

> - **性质**：不参赛项目题（无赛事锚点；含金量锚点 = HN 十年反复验证的题材热度 + 确定性可评测 + 谜题层开源空白）
> - **目标产出**：仓库 `10-19-circuit-detective`（Circuit Detective / 黑盒电路侦探），发布 GitHub **公开仓库**，署名 `yuluo554`
> - **版本史**：v1 2026-10-17（初稿定稿；需求侧与开源检索基准日 2026-10-17）
> - **交付形态**：**纯前端单页 Web 游戏**（Canvas2D 渲染，浏览器直接打开）。**零后端、零 CDN、无美术资源**；每日题用日期哈希种子，不需要数据库。单一形态，不设备选。
> - **定位宣言**："屏幕上只有一个黑色芯片盒：左边 4 个输入拨杆，右边 4 个指示灯。你拨开关、看灯亮灭，反推出盒子内部最少用了哪几个逻辑门；提交后答案揭晓，并显示你多用了几个门。**用最少次数的试探猜出黑盒里的电路**——答案由内置求解器可证明，关卡由种子确定性生成，探测序列可回放。这是'有判定内核的解谜游戏'，不是模拟器。"
> - **诚实定位**：本题不宣称"电路题材首创"，也不宣称"解谜玩法首创"。它只押一处缝隙：**把"反推黑盒"做成可视化推理循环，并用求解器给出可证明的最少门数**。同题材已有三个 2026 年的 0★ 尝试，全部做成"填真值表"的表格任务——本题的差异化入口正是它们失败的地方（见 §一）。
> - **品牌隔离**：本题是游戏，与系列内其他工具类项目无任何业务、命名、素材或文档交叉；本文档不提名任何其他项目。

**它们失败在同一个地方：把"反推电路"做成了"填真值表"的表格任务**——玩家在表格里勾 0/1，没有拨杆、没有灯、没有"我拨一下看看"的推理循环。表格任务把游戏退化成作业题：没有试探的乐趣，也没有"我离最优解还差几个门"的即时反馈。**本题必须坚持可视化揭示**（见 §二 M3 与 plan/00 决策 D2），否则会重蹈覆辙。

**为什么不是模拟器**：模拟器要的是"自由搭建 + 正确仿真"，用户是设计者；本题要的是"信息受限下的反推"，用户是侦探。前者红海，后者需要的是**求解器裁判 + 探测次数计分 + 可回放序列**，这三样都不是模拟器的功能。

**技术可行性（✅ 已核对实现路径）**：Canvas2D 足够（32×32 网格、≤200 门、60Hz 求值开销可忽略）；无美术资源（门用几何图形 + 单色 + 2px 走线动画）；体积目标 <150KB gzip（不含框架，以末态实测回填）；无需 WebGL / WebGPU / 后端（每日题 = 日期哈希种子，连数据库都不用）。

## 二、任务要求

首期 **5 个模块**，扩展项另列。每模块写清 **输入 / 输出 / 确定性纪律 / 验收**。所有数值口径（三值语义、PRNG 参数、求解器上限、短码编码）**只在 `data/README.md` §四定义一次**，代码、文案、文档一律引用该节，不得另立第二套口径。

### 模块①：门级仿真核

- **输入**：网表 JSON（门列表：类型、输入引脚引用、输出引用；输入端口列表；输出端口列表）+ 一组输入向量。
- **输出**：每个输出端口的三值结果（0 / 1 / X）+ 每个门的逐 tick 值轨迹（供动画与调试）。
- **引擎**：网表 → 拓扑排序 → 每个 tick 对所有门求值一次（**unit-delay**：门的输入取上一 tick 的值，不取本 tick）。纯整数位运算，三值用 0/1/2 编码，**无浮点**。组合环（拓扑排序无法覆盖的强连通分量）整体判为 X，不抛异常、不死循环。稳定判定：连续两个 tick 全部门值不变即视为稳定，上限为门数 + 1 个 tick。
- **确定性纪律**：门的求值顺序固定为拓扑序（同层按门 id 字典序），不依赖对象键序或 `Math.random`；X 的传播规则由 `data/README.md` §四单点定义；同一网表 + 同一输入向量在任意浏览器上逐门值相同。
- **验收**：1000 个随机网表（含环、含扇出、含未使用门）与**独立的第二实现**（另行编写、不 import 生产模块）比对，**0 差异**；环网表在有限 tick 内收敛为全 X，不挂死。

### 模块②：关卡生成器

- **输入**：`seed`（整数或日期字符串）+ 难度参数（输入位数、门数上限、门基）。
- **输出**：关卡 JSON（隐藏网表、输入/输出端口、难度标签、关卡 id）+ 该关卡的**最优门数**（由求解器给出，不是人工标注）。
- **引擎**：`seed` → xorshift128+ → 随机网表 → 等价类归约（以输出真值表为等价类键，合并同功能网表）→ 按"最少门数 + 需要多少探测才能区分候选"定难度。生成后立即跑求解器复核；不满足条件的关卡**重抽**（重抽次数上限与失败语义在 `data/README.md` §四定义），不得把不合格关卡放进关卡池。
- **确定性纪律**：同 `seed` 在任意浏览器、任意机器生成**字节级相同**的关卡 JSON；不使用时间、`Math.random`、对象键序、区域设置；重抽过程也由同一 PRNG 流驱动，因此可复现。
- **验收**：10,000 个 seed 生成的关卡**全部有解**，**多解 / 无解关卡 = 0**（"多解"指求解器无法给出唯一最少门数、导致判定歧义）；同一 seed 两次生成的 JSON 哈希相同；跨浏览器（至少两种引擎）哈希相同。

### 模块③：探测与推理交互

- **输入**：玩家的拨杆操作（4 位输入向量）、笔记内容、提交的网表。
- **输出**：输出灯的亮/灭（或 X 的闪烁态）；探测次数；提交后的结算面板（**你的门数 / 最优门数 / 差值 / 探测次数**）。
- **引擎**：每次拨动 → 调 M1 仿真核 → 读输出端口。玩家可以在画布上摆放门、连线、删除；提交时用 M1 校验提交网表的真值表是否与隐藏网表在**全部输入组合**上一致（4 输入 = 16 行，全表比对，不做抽样）。
- **确定性纪律**：观察结果**只由 M1 决定**，不得由渲染层、动画时序或任何随机量参与；探测次数只统计"输入向量发生变化"的事件，重复拨到同一状态不计数；结算差值 = 提交门数 − 求解器最优门数，计算路径单点。
- **验收**：任意探测序列的观察值都可由 `seed + 网表` 重算并逐项相同；提交后展示的"你的门数 / 最优门数 / 差值"与求解器结果 **100% 一致**；提交错误网表时给出"哪一行输入对不上"的具体反馈，而不是只报"错"。

### 模块④：回放与分享

- **输入**：一次完整游玩的操作序列（seed、探测序列、提交网表、结算）。
- **输出**：短码 / URL（`#r=<code>`）；回放视图；分享文案（含探测次数与门数差）。
- **引擎**：操作序列 → 确定性编码 → 短码；解码后用同一 M1/M2 重建全过程，逐项重演。编码只允许使用 URL 安全字符；版本号进编码前缀，旧码在新版本上要么可解、要么明确报"版本不兼容"，不得静默错解。
- **确定性纪律**：操作序列 + `seed` **完全决定**全过程；短码不含时间戳、机器信息、随机盐；同一操作序列编码结果唯一。
- **验收**：两台机器 / 两个浏览器重放同一短码，产生**逐项相同**的探测结果序列；短码长度 **≤ 64 字符**；篡改一位后能被校验位识别（报错而非错误回放）。

### 模块⑤：校验 CLI

- **输入**：仓库源码 + `npm run verify`。
- **输出**：一条命令跑全量自检：仿真核交叉验证、种子生成 10k 的耗时 p50 / p99、求解器复核通过率、跨实例回放一致率、构建产物静态扫描（无外链 / 无 CDN）。输出人类可读摘要 + 机器可读 JSON。
- **确定性纪律**：`verify` 本身不写随机数；所有用例由固定 seed 派生；耗时统计只报告不参与判定（避免机器性能导致红绿抖动）；判定项只有"通过率 / 差异数 / 外链数"。
- **验收**：`npm run verify` 一条命令可跑；输出**种子生成 10k 耗时 p50 / p99**、**求解器复核通过率 100%**、**跨实例回放一致率 100%**；CI 中任一项失败即红。

### 扩展项（不进首期）

- **时序 / 触发器关卡包**：波形谜题（候选 B），需要引入时钟与状态机语义，首期不做。
- **自定义关卡编辑器**：玩家自建黑盒并分享，需要额外的可解性校验与难度标注，首期不做。
- **多人联机**：竞速或对抗，首期不做。

## 六、边界与非目标

- **不做电路模拟器**：不追求自由搭建、不替代 logisim / Digital 这类工具；没有元件库、没有模拟波形分析、没有导入导出标准网表格式。玩家摆放门只为"提交答案"，不是设计电路。
- **不做多人联机（首期）**：竞速与对抗需要服务端或 WebRTC，且确定性难以在一周内保证，留扩展项。
- **不做自定义关卡编辑器（首期）**：自建黑盒需要额外的可解性校验与难度标注，留扩展项。
- **不做"AI 生成关卡"**：关卡必须由**求解器可证明**，任何"模型生成 + 人工觉得可以"的路径一律不采用；生成器只用 PRNG + 求解器。
- **不做排行榜**：无后端，日期种子可被客户端提前算出（当天题目在本地就能生成），排行榜必然可刷；**可接受，但砍排行榜**。
- **不做账号、不做云存档**：进度只存 `localStorage`，清空即失，不承诺跨设备同步。
- **隐私红线**：纯前端，**零上传、零遥测、零第三方请求**；构建产物不得包含任何外部 URL（字体、图片、统计脚本一律不引）。
