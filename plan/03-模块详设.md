# 03 · 模块详设（M1–M5）

> 状态：M1/M2/M4 的**内核部分**已在 M0 骨架里实现（仿真核、生成器、求解器、短码），并已有测试与 `verify` 覆盖。

## M1 · 门级仿真核

**输入**：`{inputs[], outputs[], gates[{id,type,in[]}], outputsMap{}}` + 输入向量（数组或对象）。
**输出**：`{ok, outputs, gates, stable, ticks, trace[], diagnostics[], errors[]}`。

实现要点（`src/core/sim.mjs`）：

1. `validateNetlist` 两遍校验：先收集信号名（允许前向引用），再校验引脚引用与门类型。
2. `topoOrder`：Kahn 分层，同层按门 id 升序；覆盖不到的门 = 组合环成员。
3. 每 tick：读**上一 tick** 的门值 + 本 tick 的输入端口值 → 算本 tick 门值；环成员强制 X。
4. 稳定判定：`tick > 0` 且门值表与输出值表同时不变；上限 `门数 + 1`，超限按全 X 并记诊断。
5. 三值规则单点在 `data/README.md` §4.1；`NOT`/`AND`/`OR` 的 X 传播在 `applyGate` 一处实现。

**失败路径**：非法网表结构化返回；环不抛异常；不稳定不静默返回部分结果。

**已实现验收**：`tests/sim-cross.test.mjs` —— 1000 条 fixture × 全部输入组合（9,540 次）与独立第二实现（`tests/reference/sim-reference.mjs`，不 import 生产模块）逐门逐输出比对 **0 差异**；200 条含环 fixture 均收敛、环成员恒 X。

## M2 · 生成器与求解器

**生成链路**：`seed → createRng → randomNetlist → truthTableMasks → solveOptimal → 接受/重抽`。

- 重抽上限 64（`MAX_REDRAWS`），超限显式失败，不换 seed、不放宽约束。
- 接受条件：网表合法、无 X、至少两个不同输出函数、最优门数在 `[minOptimal, gateBudget]`。
- 关卡 JSON 由 `levelToJson` 固定键序输出；同 seed 两次生成逐字节相同。

**求解器口径**（`data/README.md` §4.3）：

- 单输出最少数 = 二输入 `AND`/`OR` + `NOT` 的**公式复杂度**，用按门数递增的成本表精确求出（16 位掩码为状态，`cost[mask]` 为最少门数）。
- 多输出 = 每个输出锥内部门数之和；**共享门按使用它的输出各计一次**。
- 未使用门不计分（玩家草稿不惩罚）。
- 不可达返回 `-1` 并显式报 `unreachable`，不猜。

**已实现验收**：`npm run verify` 的 `level.generation` 段 —— 10,000 seed 全部成功、多解/无解 = 0、求解器复核通过率 100%、p50 / p99 实测打印；`tests/generator.test.mjs` 断言同 seed 字节级一致。

## M4 · 回放与分享

**已实现（内核）**：`src/core/replay.mjs`

| 字段 | 位宽 |
| --- | --- |
| 版本 | 8 bit（当前 = 1） |
| seed | 64 bit（高 32 + 低 32） |
| 探测步数 | 8 bit |
| 每步输入向量 | 4 bit |
| 门数 | 4 bit（上限 12） |
| 每门 | 类型 2 bit + 输入引脚 4 bit × 2 |
| 每个输出端口 | 来源信号 4 bit |
| CRC16-CCITT | 16 bit |

编码 Base64url 无填充；长度上限 64 字符；超长显式报错不截断。
`verify` 的 `replay.crossInstance` 段用**独立子进程**解码重演，与主进程逐项比对。

**待实现**：`#r=<code>` 路由（加载回放而不是关卡）、回放视图（按步推进探测）、分享文案（探测次数 + 门数差）。

**验收（M4 DoD）**：两浏览器重放同一短码逐项相同；篡改一位被 CRC 识别；短码 ≤64 字符。
