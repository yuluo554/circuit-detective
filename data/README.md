## 三、合成数据纪律

- **关卡是生成的，不是采集的**：所有关卡由 `seed` 经 xorshift128+ 生成，并由求解器复核；不存在"真实关卡数据集"。
- **fixture 中的网表必须标注为合成**：`data/fixtures/` 下每个 JSON 含 `"synthetic": true` 与生成它的 seed；不得把合成网表描述为"来自某真实芯片"。
- **无需假号段 / 假 DOI 白名单**：本题不涉及个人信息、电话、身份证、DOI、政策文号等易被误认为真实的标识。若后续扩展项引入玩家昵称示例，统一使用明显的占位名（如 `player-01`），不得使用真实姓名。
- **禁止**把 HN 条目、仓库星数等文档论据写进运行时数据或关卡描述，避免"引用快照被当成事实数据"。
- **不编造**：任何未核对的数字（如商业销量）不得出现在题面、README、界面文案中。

## 四、数值口径（唯一出处）

> 代码、文案、plan/01、plan/03 一律引用本节；**禁止在别处手写第二份口径**。

### 4.1 三值逻辑与 unit-delay

- 三值编码：`0` = 逻辑 0，`1` = 逻辑 1，`2` = X（未知 / 冲突）。内部一律用整数，**禁止浮点参与求值**。
- **unit-delay 语义**：每个 tick，所有门读取**上一 tick** 的输入值并计算本 tick 输出；门的输出在下一 tick 才对下游可见。输入端口在 tick 0 即取玩家给定的向量值。
- **求值顺序**：按拓扑序求值，同层按门 `id` 字典序（字符串升序）。求值顺序不影响 unit-delay 结果，但必须固定以保证轨迹可复现。
- **X 传播**（按门类型，单点定义）：
  - `NOT`：`0→1`、`1→0`、`X→X`
  - `AND`：任一输入为 `0` → `0`；否则若任一输入为 `X` → `X`；否则 `1`
  - `OR`：任一输入为 `1` → `1`；否则若任一输入为 `X` → `X`；否则 `0`
  - 扩展门基（二期）在此表追加，不改动既有行。
- **组合环**：拓扑排序无法覆盖的强连通分量，其中所有门在**每个 tick** 输出 `X`；不抛异常、不死循环。
- **稳定判定**：连续两个 tick 全部门值与输出端口值均不变即视为稳定；上限 `门数 + 1` 个 tick，超限则判定为不稳定（视为全 X）并记录诊断，不静默返回部分结果。

### 4.2 PRNG 与生成

- **算法**：xorshift128+，128 位状态（两个 64 位字），输出取 `s0 + s1` 的高 53 位转整数（具体实现常量随代码冻结，改动需新增口径版本行）。
- **seed 归一**：整数 seed 直接取低 64 位；日期字符串 `YYYY-MM-DD` 先按 UTF-8 取 FNV-1a 64 位哈希再取低 64 位。
- **禁止**：`Math.random`、`Date.now`、`performance.now`、对象键序、`Intl` / 区域设置、`toLocaleString` 参与任何生成或判定。
- **重抽上限**：单个 seed 最多重抽 **64** 次；超过则判定该 seed 不可用，返回显式错误（不静默换 seed、不静默放宽难度）。
- **难度分档**：由求解器给出的最优门数决定，`easy` ≤ 2 门、`normal` 3–4 门、`hard` ≥ 5 门（首期分档只影响标签与关卡排序，不影响判定）。
- **字节级一致**：关卡 JSON 的键顺序固定为声明顺序，数字统一十进制整数，不含时间戳与机器信息；同 seed 两次生成的 JSON 字符串哈希必须相同。

### 4.3 求解器

- **判定目标**：在声明的门基（首期 `NOT` / `AND` / `OR`）与门数上限（首期 **12** 门）内，找到实现隐藏网表全部输入输出行为的**最少门数**。
- **门数口径（D14 / D21）**：**每个输出端口单独计数**——沿该输出端口的上游展开到输入端口，**每引用一个门计一次**；同一个门被两个输出共用时各计一次，同一输出内的重复引用也各计一次。未被任何输出引用到的门**不计分**、也不参与提交校验。该口径等于"逐输出公式规模之和"，因此 `countedGates(提交) − optimal ≥ 0` 恒成立（M3 实测 400 关差值全部非负）。界面与文档必须写明"按每个灯单独计门"，不得暗示这是理论绝对最优（对应 plan/01 §六 结论纪律）。
- **单输出最少数 = 公式复杂度（D15）**：以 16 位输出掩码为状态，门基为二输入 `AND` / 二输入 `OR` / 一元 `NOT`，按门数递增做精确分层动态规划；`cost[mask]` 即该函数的最少门数。该成本表只与输入变量数有关，进程内建一次（D16）。
- **等价类**：以输出真值表（4 输入 = 16 行，每行 4 位输出）为键；同键的网表视为等价，取门数最小者。
- **搜索上限**：枚举按门数递增，超过门数上限即终止，该函数判为**不可达**并显式返回 `-1` / `"unreachable"`；**不得返回猜测值**。
- **"多解"判定**：若在最少门数下存在多个**功能不等价**的候选无法区分（即隐藏网表的行为无法由任何输入向量唯一确定），判为多解关卡，禁止入池。同功能不同结构的网表不算多解。首期实现里"可区分"取保守形式：输出函数必须至少两个不同取值（排除全 0 / 全 1 退化关卡），且输出端口之间不得全部相同。
- **唯一裁判**：结算面板与生成期复核使用**同一求解器**；不存在第二套"人工标准答案"。
- **生成期结构约束（D22）**：隐藏网表不得含恒等冗余门（`AND(x,x)` / `OR(x,x)` 等价于 `x`，会给出玩家看不出的死结构）；`generateLevel` 在候选阶段显式剔除，`verify` 与测试常驻断言。

### 4.4 交互与计分

- **探测次数**：仅当输入向量**发生变化**时 +1；拨回同一向量不计数；初次进入关卡不计。
- **结算差值** = 提交网表门数 − 求解器最优门数；差值 ≥ 0。提交网表功能不正确时不给差值，只给"哪一行输入对不上"。
- **提交校验**：全表比对 16 行（4 输入的全部组合），不抽样、不随机抽点。结构校验（未接线 / 悬空引用 / 环）先于比对，一次列全。
- **揭示动画**：按拓扑层级从输入侧向输出侧逐层点亮；每层停留时间固定，不做随机抖动；`prefers-reduced-motion` 时直接呈现最终态。
- **术语门槛（D1 / D20）**：前 3 关界面只出现"黑盒 / 开关 / 灯 / 拼块 / 插口"，不出现"门"及 `AND` / `OR` / `NOT` / `NAND`；第 4 关起才用正式名称。文案单点在 `src/ui/copy.mjs`，`verify` 的 `copy.terms` 段与 `tests/copy-gate.test.mjs` 常驻扫描。

### 4.5 回放短码

- **位布局（版本 1，D15/M4 实现口径）**：版本 8 bit + seed 高 32 bit + seed 低 32 bit + 探测步数 8 bit + 每步输入向量 4 bit + 门数 4 bit + 每门（类型 2 bit + 输入引脚 4 bit × 2）+ 每个输出端口的来源信号 4 bit + CRC16-CCITT 16 bit。信号下标 = `[inputs..., gates...]` 的数组位置，首期上限 16 个信号（4 输入 + 12 门）。
- **seed 编码**：整数 seed 取低 64 位；字符串 seed 先 FNV-1a 64 位再编码（解码侧只能拿到整数，**字面 seed 文案不进短码**）。解码侧必须还原成**无符号 64 位**（`read(32) >>> 0`）：用 JS 有符号位运算一次读 32 bit 会把高位置 1 的 seed 变成负数（D25）。
- **编码**：Base64url（无填充），字符集 `A-Z a-z 0-9 - _`。
- **长度上限**：**64 字符**；超出则提示"本次操作过长，无法生成短码"（不截断、不丢步骤）。
- **校验**：CRC16-CCITT（初值 `0xFFFF`，多项式 `0x1021`）覆盖 CRC 之前的全部字节；篡改一位必须被识别为"校验失败"。
- **兼容**：解码时先读版本号；不认识的版本 → 明确报"版本不兼容"，不得尝试按当前版本解析。
- **分享文案（D9/D27）**：探测次数 + 门数差 + 短码；短码超长时**降级**为"原始种子文案 + 探测次数"（降级只发生在分享文案层，短码本身绝不截断）。文案落在 `src/ui/copy.mjs`，前 3 关词表不含"门"。
- **回放路由（D27）**：`#r=<code>` **优先于** `#s=<seed>`；短码不可用（校验失败 / 版本不兼容 / 截断 / 非法字符）时明确报错并清空局面，**不得**退化成普通关卡；解码成功时地址栏保留原 `#r=`。
- **回放视图（D26/M4）**：只读（提交 / 清空 / 删除 / 摆件 / 关卡切换全部禁用，点画布与数字键都不改变状态）；探测次数 = 短码里的步数，**不重新计数**；步表 = 用短码里的网表对探测序列重算（`recomputeProbes`）；揭示与回放共用 `buildRevealPlan`，按 tick 同时推进"探测步"与"揭示层"，末尾同到终态；短码不含关卡号，因此回放一律用**无术语词表**。

### 4.6 渲染与体积

- **画布**：逻辑网格 32×32；走线宽 2px；门用几何图形 + 单色描边，无位图资源。
- **帧率**：交互态 60Hz；仿真求值按 tick 推进，与渲染帧解耦（同一 tick 不重复求值）。
- **体积目标**：`dist/index.html` < 150KB gzip（不含框架，因为不使用框架）；末态实测值回填到 `docs/verify-sample.txt`，不写进 plan/01 正文。
- **零外链**：构建产物不得包含 `http://` / `https://` 字面量（含注释与字符串常量），不得引用 CDN、外部字体、统计脚本。
